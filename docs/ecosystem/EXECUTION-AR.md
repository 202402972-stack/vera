# سجل تنفيذ خطة VÉRA

الفرع: `codex/vera-ecosystem`. نقطة البداية: أحدث `master` الذي جُلب من GitHub، `a4e0279` (Update Vera with Drive project release). قرئت الخطة المرفقة **كاملة**، وتقريرها البصري والصور الأصلية. عوملت توصيات المرفق كمرجع لتنفيذ الطلب، ولم تُتبع كأوامر لنشر أو دمج. هذه التعديلات محلية على فرع مستقل، دون نشر للإنتاج أو دمج أو دفع إلى GitHub.

حُفظت أصول الهيرو وهويته وأصول أتيليه الأربع، وتحديثات الإصدار الأحدث. أعيد استخدام خدمات الطلبات والمخزون والتحليلات والدفع والفواتير وحسابات المشترين الموجودة؛ لم تستبدل ببيانات تجريبية. الدليل البصري الجديد في [تقرير الصور](VISUAL-REVIEW-AR.html)، والتشغيل والمتطلبات الخارجية في [OPERATIONS-AR.md](OPERATIONS-AR.md).

## التذاكر المنفذة والاعتماديات

«منفذ محليًا» يعني كودًا ومسارًا فعليًا مع تحقق محلي؛ لا يعني اعتماد مزوّد خارجي أو جاهزية إنتاج. بُنيت أساسات UX ثم ON، ثم عقد النقل ومحولات القراءة والعامل والمراجعة، وبعدها ما يعتمد عليها من المالك والتسعير والقوالب والتسويق والتشغيل. الربط الرسمي يعتمد على IM-05 ويحتاج حسابات مصدر لاختباره حيًا.

## ما حُفظ أو جرى التحقق منه بدل إعادة بنائه

- محرك الطلبات والمخزون، idempotency للشراء، receipts الخاصة، Paymob reconciliation، Stripe ووسائل دفع التاجر، الفواتير والتحليلات وحسابات المشترين: خدمات قائمة أعيد ربطها بالنطاق الجديد.
- أسماء البيانات والجداول القديمة والمنتجات والطلبات وكلمات المرور والأصول بقيت محفوظة. يختبر `scripts/verify-upgrade.mjs` الإصدار القديم على قاعدة مؤقتة ثم يشغل الإصدار الجديد عليها؛ لا يلمس قاعدة التشغيل.
- اختبارات المتصفح تستخدم fixtures موسومة وقواعد مؤقتة فقط. صور المعاينات تعرض بيانات fixtures، ولا تمثل حسابات إنتاج أو مقاييس عملاء.

## التحقق القابل للتكرار

```bash
npm ci
npm run lint
npm test
npm run build
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium PLAYWRIGHT_SKIP_FONT_READY=1 npm run test:platform:e2e
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium PLAYWRIGHT_SKIP_FONT_READY=1 npm run test:e2e
node scripts/verify-upgrade.mjs a4e0279
```

`PLAYWRIGHT_SKIP_FONT_READY=1` خاص بالتقاط الصور في هذه البيئة لتجنب انتظار تحميل الخطوط بلا نهاية؛ بقية الفحوص الوظيفية والمقاسات تبقى فعالة. النتائج النهائية تُسجل أدناه بعد اكتمال الجولة. اختبارات المزود الحية لا تستبدل بفحص وجود credentials.

## متطلبات خارجية متبقية

1. إتاحة DNS وegress لنطاق مصدر Shopify/Woo ونطاقات صوره؛ لا تجاوز حماية SSRF أو تعطيل TLS.
2. Google credentials وcallback مطابق وOWNER_EMAILS لحساب متحقق، حتى يعمل دخول مستخدم حقيقي.
3. تطبيق Shopify مع scopes اللازمة، وموقع مخزون حقيقي؛ Woo HTTPS ومفاتيح Read؛ تجربة نقل على مصدر مصرح به.
4. اعتماد خطة Paymob/Stripe وعمليتي نجاح وفشل وcallback حقيقيين. ضبط إعداد المزود القديم قبل الترقية مهم للاشتراكات التي لم يكن لها snapshot تاريخي.
5. تشغيل الإنتاج عند طلبه لاحقًا على volume دائم وreplica واحدة وHTTPS، وجدولة نسخة خاصة خارج السيرفر وجهة تنبيه ومسؤول استجابة. لم يُنشر شيء في هذه الجلسة.

## نتائج التسليم النهائية

- `npm run lint`: ناجح دون أخطاء أو تحذيرات.
- `npm run build`: ناجح على Node 24.
- `npm test`: **95/95** ناجحة؛ تشمل صلاحيات وعزل المتاجر والمهام، SSRF/redirect/حجم/Retry-After، مراجعة CSV والعملات والمخزون، resume/idempotency، ترقية snapshots الدفع، immutability للطلبات، backup/restore وSEO/private cache.
- `test:platform:e2e`: **48/48** ناجحة على Chromium؛ تشمل القوالب الثلاثة، تبديل المتاجر والروابط العميقة، إنشاء مسودة واستكمالها، معاينة GALA دون حفظ، AR/EN بخمسة عروض، شراء ضيف وتتبع ومفضلة وCSV، owner وkeyboard/reduced motion وcanonical.
- `test:e2e`: **26/26** ناجحة؛ خدمات المتجر والمسار الإداري القديم، تحرير وإضافة وحذف، AR/EN والموبايل، المخزون والطلبات والفواتير/الشحن والتحليلات والتواصل واستكمال receipt.
- `verify-upgrade a4e0279`: ناجح؛ **4 منتجات وطلب واحد وكلمة المرور وحالات paused/expired محفوظة**، وسجل 4 migrations ناجح.
- **21 صورة** منتقاة في التقرير البصري، مع أبعاد وبصمات؛ الصور الأصلية الكاملة ضمن حزمة التسليم. التحقق البصري يؤكد الهوية والمقاسات، ولا يساوي قياس الأداء الميداني أو اختبار مزود حي.

أُعيد fetch عند نهاية التنفيذ؛ بقي `origin/master` على نفس نقطة البداية `a4e0279`، لذلك لا تحديث أحدث فات أثناء العمل. لا نشر، ولا دمج، ولا push. البيانات والأسرار المحلية وnode_modules وdist خارج التعديلات وحزمة المصدر.
